NeuralBlockCompressor - command cheat sheet
============================================

Run everything from the repo root with the venv active:
    source .venv/bin/activate        (Windows git-bash: source .venv/Scripts/activate)
(If not set up yet: ./setup.sh creates the venv, installs deps, downloads datasets.)


1. Training
-----------
Checkpoints are written to checkpoints/bc7_<mode>_<arch>.pt
(e.g. checkpoints/bc7_mode6_mlp.pt, checkpoints/bc7_mode5_mlp.pt).

BC7 mode 6 (RGB, no alpha):
    python src/train_bc7.py --mode mode6 --epochs 15 --batch-size 32768

BC7 mode 5 (RGBA / alpha textures):
    python src/train_bc7.py --mode mode5 --epochs 60 --val-images 4 --batch-size 4096

BC5 (normal maps, R+G as two independent BC4 lines): NO NETWORK. A BC4 line is
1-D and the block's min/max is already a near-optimal endpoint pair; min/max +
2 refinement rounds (src/bc5_codec.py encode_bc5_blocks) scores ~53.5dB on
data/normal vs ~53.7dB ISPC / ~53.2dB Compressonator, whereas a BC5 MLP
(since removed) only reached ~46dB: its too-wide endpoint guesses collapsed
low-contrast blocks to their mean.
    Dataset is data/normal (sponza normals already there), used by the
    benchmarks. One-time: copy the bistro + intel_sponza normal maps
    (*Normal*.png; bistro's 1x1 placeholders and flat constant maps are
    skipped) next to them:
        python src/collect_normal_maps.py
    Packer self-test (encode -> pack -> texture2ddecoder must match bit-exactly,
    also prints the ISPC BC5 PSNR of the given image, ~43dB on sponza):
        python src/bc5_codec.py --image data/normal/2299742237651021498.jpg

BC6H (HDR, RGB half-float, mode 11): NO NETWORK, like BC5. Endpoints start at
the block's per-channel min/max and get the same 2 least-squares refinement
rounds (src/bc6h_codec.py encode_bc6h_blocks); everything works in the
half-float-bits-as-integer domain BC6H interpolates in (values / 0x7BFF), and
PSNR is reported in that domain ("PSNR half-int", ~relative error). Scores
~45.7dB over 20 HDR validation images vs ~49.4dB for ISPC's full 14-mode
search (the gap is mostly the higher-precision single-subset modes 12/13 and
the two-subset modes, which we don't emit -- same story as BC7 mode 6/5 only).
A mode-11 MLP (per-block normalised input, exact-index loss) gave better
endpoints than min/max BEFORE refinement (43.7 vs 42.6dB) but the refinement
erased the difference (45.67 vs 45.72dB), so it was removed.
    Dataset: DIV2K converted to Radiance .hdr with oiiotool (brew install
    openimageio): sRGB -> linear, long side 1024, random per-image exposure
    (log-uniform 2..32, seeded by file name) so values go well above 1.0.
    ~2GB; data/hdr/valid is what the benchmarks use:
        python src/convert_hdr_dataset.py            -> data/hdr/{train,valid}/*.hdr
    Packer self-test (encode -> pack -> our all-mode BC6H decoder must match;
    also prints the ISPC BC6H PSNR of the image). texture2ddecoder's BC6
    decode only returns clamped 8-bit, so src/bc6h_codec.py carries its own
    14-mode decoder (tables generated from DirectXTex, src/bc6h_tables.py):
        python src/bc6h_codec.py --image data/hdr/valid/0801.hdr

ASTC 4x4 (three texture kinds, see src/astc_codec.py): NO NETWORK for any of
them -- the same story as BC5/BC6H, measured the same way. A generic
single-partition 4x4 block config (colour endpoint mode x weight range x
optional second weight plane) was written in Python (bit-exact against ARM's
astcenc, vendored in c_api/third_party/astcenc, for LDR and HDR) and every
candidate config was scored with block min/max init + 2 refinement rounds on
validation subsets; the shipped shortlists, picked per block by squared error
like BC7 mode 6/5, are (astcenc -medium in brackets, mean PSNR):
    GAME   RGBA8 (albedo / packed metal-rough / emissive, cutouts):
           A  = CEM 8 RGB, 4-bit weights, QUANT_192 (trit) endpoints
           A3 = CEM 8 RGB, 3-bit weights, QUANT_256 endpoints (wins on smooth
                textures: 8-bit endpoints matter more than 16 weight levels)
           B  = CEM 12 RGBA, 2-bit weights, alpha in its own weight plane,
                QUANT_48 endpoints (the alpha config, like BC7 mode 5)
           A+B 52.3 dB, A+A3+B 54.3 dB over 20 val textures [58.0]
    NORMAL (X,Y) stored as CEM 4 luminance + alpha (astcenc's -normal layout,
           sample .ra): A = 4-bit weights, one plane; B = 2-bit weights, two
           planes (BC5's two independent lines), both QUANT_256. B alone
           44.1 dB, A+B 45.1 dB over 8 val maps [47.7]
    FLOAT  HDR RGB as CEM 11 with 3-bit weights and QUANT_256 (the HDR
           endpoint packing needs full 8-bit values; the whole codec works in
           ASTC's LNS domain, x = lns16 / 65535): 43.0 dB (LNS domain) over 8
           val images [47.7]
    (The gap to astcenc is the usual one: partitions, decimated weight grids
    and the other endpoint modes, none of which we emit -- same as BC7/BC6H.)
Then one MLP per kind was trained (64 -> 128 x3 -> 24, the BC7 mode-6
geometry, exact-index loss like BC6H) and compared against the min/max init
*after* refinement on 262k validation blocks:
    kind    net input        net / min/max after refinement
    NORMAL  raw (x,y)        37.43 / 38.01 dB   (15 epochs)
    NORMAL  block-normalised 37.57 / 38.01 dB   (10 epochs)
    FLOAT   block-normalised 42.42 / 42.43 dB   (15 epochs, half-int domain)
    GAME    raw RGBA         41.35 / 41.84 dB   (plateaued at epoch 5 of 15)
    GAME    block-normalised 41.39 / 41.84 dB   (8 epochs on 400 images)
(For scale: the shipped BC7 mode-6 net scores the same way -- 41.26 dB
from the net vs 42.22 dB from min/max after 2 refinement rounds on 6 DIV2K
validation images -- the least-squares refinement, not the init, is what
does the work. Worth revisiting for BC7.)
No kind beat the bounding box by the 0.3 dB we asked for, so the C library
encodes all three analytically and the ASTC networks (training modes, model
loading, tensor kernel) were removed.
    Codec self-tests (ISE/quantization tables vs the vendored astcenc source
    tables; pack -> own decoder -> texture2ddecoder (LDR, +-1 LSB rounding) ->
    astcenc CLI decode must be bit-exact, incl. HDR; needs c_api/build for
    the astcenc-neon CLI):
        python src/astc_ise.py
        python src/astc_codec.py --image data/ambientcg_alpha/Fence001.png \
            --normal data/normal/2299742237651021498.jpg --hdr data/hdr/valid/0801.hdr
    The Metal kernels' constant tables are generated from the same source:
        python src/astc_ise.py --emit-metal > c_api/src/shaders/anbc_astc_tables.metal

Useful extra flags (see src/train_bc7.py):
    --limit-images N     train on only the first N images (quick smoke test;
                         note it overwrites checkpoints/bc7_<mode>_mlp.pt)
    --val-images N       number of validation images (default 20)
    --lr 1e-3            learning rate
    --hidden-dim 128     MLP hidden width
    --device cuda|mps|cpu   auto-detected by default


2. Compare UI (original vs ISPC vs neural, synced zoom/pan)
-----------------------------------------------------------
Mode 6 only:
    python src/compare_ui.py --image data/div2k/train/<some_image>.png --model checkpoints/bc7_mode6_mlp.pt

Mode 6 + mode 5 with real per-block mode selection (pass --model twice, mode6 first):
    python src/compare_ui.py --image data/ambientcg_alpha/Fence001.png \
        --model checkpoints/bc7_mode6_mlp.pt --model checkpoints/bc7_mode5_mlp.pt

BC5 normal map (original vs ISPC BC5 vs ours; no model needed; panels show the
normal map with Z reconstructed from RG, PSNR is over the two stored channels):
    python src/compare_ui.py --image data/normal/2299742237651021498.jpg --bc5

BC6H (.hdr input; original vs ISPC BC6H full search vs ours, panels tone-mapped,
PSNR half-int + HDR-FLIP; no model needed):
    python src/compare_ui.py --image data/hdr/valid/0801.hdr --bc6h

ASTC 4x4 (original vs astcenc -medium vs ours; game on RGB(A), normal on the
two stored channels with Z reconstructed, float tone-mapped + half-int PSNR;
no model needed):
    python src/compare_ui.py --image data/ambientcg_alpha/Fence001.png --astc game
    python src/compare_ui.py --image data/normal/2299742237651021498.jpg --astc normal
    python src/compare_ui.py --image data/hdr/valid/0801.hdr --astc float

Optional: --device cuda|mps|cpu (auto-detected by default)
Optional: --refine-iters N (default 2) -- rounds of exact index search +
    least-squares endpoint refit applied to the model output before packing
    (the net only provides the initial endpoints). 0 = raw model output.
    Both compare_ui.py and benchmark.py take this flag.


3. Benchmark (batch over a folder: avg speed + PSNR/FLIP vs ISPC)
-----------------------------------------------------------------
Mode 6 only (defaults to checkpoints/bc7_mode6_mlp.pt if --model is omitted):
    python src/benchmark.py --folder data/div2k/train --model checkpoints/bc7_mode6_mlp.pt

Mode 6 + mode 5 with per-block mode selection:
    python src/benchmark.py --folder data/ambientcg_alpha \
        --model checkpoints/bc7_mode6_mlp.pt --model checkpoints/bc7_mode5_mlp.pt

BC5 over the normal-map set (vs ISPC BC5; no model needed; PSNR on RG, FLIP on
the reconstructed normal map). The Python/torch timings mean little here --
ISPC BC5 is a trivially cheap encoder and the torch path is per-kernel
overhead bound; the real numbers are the C library's below:
    python src/benchmark.py --folder data/normal --bc5

BC6H over a folder of .hdr files (vs ISPC BC6H; no model needed):
    python src/benchmark.py --folder data/hdr/valid --bc6h

ASTC 4x4 over a folder (vs the vendored astcenc CLI, -medium by default, all
cores; --configs A,B,... to score other config shortlists from
astc_codec.ALL_CONFIGS, --limit N):
    python src/benchmark.py --folder data/bistro --astc game
    python src/benchmark.py --folder data/normal --astc normal
    python src/benchmark.py --folder data/hdr/valid --astc float

Note: the default --folder is data/sponza_albedo, which is not in data/ by
default, so always pass --folder explicitly (or drop your own textures there).


4. C library (c_api/) -- Metal 4 (macOS) / Vulkan (Windows, Linux), all mips on the GPU
----------------------------------------------------------------------------------------
Two backends behind one API (anbcCreateDevice(ANBC_DEVICE_BACKEND_METAL / _VULKAN)):
  * Metal 4 -- what ships on Apple platforms; scalar + tensor-ops BC7 kernels.
  * Vulkan  -- Windows / Linux. Plain Vulkan 1.1 compute, GLSL ports of the same
    kernels (c_api/src/shaders/glsl, glslc -> SPIR-V at build time), scalar MLP
    only (no cooperative-matrix extensions), regular device-local + staging
    memory. It needs no Vulkan SDK to *compile*: c_api/src/anbc_vulkan.h is the
    subset of vulkan_core.h we use (generated by tools/gen_vulkan_header.py,
    ABI-checked by tools/check_vulkan_abi.py / the anbc_check_vulkan_abi target)
    plus a dlopen/LoadLibrary loader for vulkan-1.dll / libvulkan.so.1 /
    libvulkan.1.dylib (MoltenVK). On macOS it exists for testing only:
    `--backend vulkan` runs it through MoltenVK, `--xcheck` runs both backends
    on one image and compares (the blocks come out bit-identical except for
    the odd fast-math tie; the check fails above 0.05 dB).
  Everything the backends load at runtime -- the runtime-compiled Metal sources,
  the BC7 tensor .metallib and every SPIR-V module -- is one blob
  (tools/pack_blob.py -> build/generated/anbc_blob_data.h, anbc_blob.h reads it).

Single header: c_api/dist/anbc.h (committed; regenerate with
`cmake --build c_api/build --target anbc_amalgamate` after touching sources or
shaders). It is the public API plus, under ANBC_IMPLEMENTATION, every source
and the blob. Define ANBC_IMPLEMENTATION in exactly one translation unit:
    macOS            anbc_impl.mm  (Objective-C++; links Metal + Foundation) -> Metal (+ Vulkan for testing)
    Windows / Linux  anbc_impl.c   (C11; Linux: -ldl on old glibc)           -> Vulkan

Export the trained networks to the .bin format the library loads:
    python src/export_weights.py            -> checkpoints/bc7_mode6.bin, bc7_mode5.bin
    (v2 files carry a format word; the library still reads the old v1 files.
    BC5, BC6H and ASTC need no network: anbcCompress(..., ANBC_TEXTURE_FORMAT_BC5 /
    _BC6H / _ASTC_4x4_*, ...) works right after anbcCreateDevice.)

Build (needs macOS 26+ / a Metal 4 GPU for the Metal backend, glslc from the
Vulkan SDK on PATH for the Vulkan kernels; the test tool also wants the
Vulkan loader / MoltenVK at runtime for --backend vulkan):
    cmake -S c_api -B c_api/build && cmake --build c_api/build -j
The astcenc reference in the test tool is built for NEON (ASTCENC_ISA_NEON in
c_api/CMakeLists.txt); an x86 host needs the SSE variant there before
anbc_compare builds -- the library itself has no such dependency.

Two BC7 inference kernels (Metal; Vulkan has the scalar one only):
  * scalar  -- every Metal 4 GPU; compiled from source at runtime (no toolchain needed).
  * tensor ops -- M5-class GPUs only (MTLGPUFamilyApple10): the MLPs run as
    matmul2d on the neural accelerators (~8x faster, identical output). It uses
    MetalPerformancePrimitives, whose implementation (libTensorOps.rtlib) only
    the OFFLINE Metal linker can resolve, so this kernel is precompiled to a
    .metallib at build time and embedded. That needs the Metal toolchain:
        xcodebuild -downloadComponent MetalToolchain
    Without it CMake warns and builds the scalar kernel only.
    Caveat: MTL_SHADER_VALIDATION=1 makes matmul2d return zeros on the current
    macOS 27 beta (verified with a standalone test), so validate with the
    scalar path (--no-tensor-ops) or MTL_DEBUG_LAYER=1 only.

Compare against Compressonator (CMP_Core BC7 + BC6H + BC4/BC5 kernels, vendored in
c_api/third_party, multithreaded, full mip chain -- same box filter as the GPU
path) and write .dds files with the full mip chain:
    c_api/build/anbc_compare data/ambientcg_alpha/Fence001.png --out /tmp     (single image: prints PSNRs)
    c_api/build/anbc_compare data/bistro --out out/bistro                      (folder: timings + summary.csv)
BC5 (normal maps; DDS written as BC5_UNORM, PSNR over R+G; ~0.8ms per 1024^2
with mips on an M5, ~7x faster than 10-thread Compressonator at equal quality):
    c_api/build/anbc_compare data/normal/2299742237651021498.jpg --format bc5 --out /tmp
    c_api/build/anbc_compare data/normal --format bc5 --out out/normal
BC6H (.hdr input, uploaded as RGBA16F; DDS written as BC6H_UF16, PSNR in the
half-int domain; ~1.3ms for a 4096x2048 HDRI without mips on an M5 and
~4.3ms for 8192x4096, vs 2.1s / 8.5s for 10-thread Compressonator at ~1dB
higher quality):
    c_api/build/anbc_compare data/hdr/valid/0801.hdr --format bc6h --out /tmp
    c_api/build/anbc_compare data/hdri_test/spree_bank_8k.hdr --format bc6h --no-mips --out /tmp
    c_api/build/anbc_compare data/hdr/valid --format bc6h --out out/hdr

ASTC 4x4 (reference = ARM astc-encoder, vendored in c_api/third_party/astcenc
and linked into the tool: -medium on all cores by default, its decoder scores
both outputs; the astcenc-neon CLI is built alongside for the Python side).
--format astc is LDR RGBA (DDS as ASTC_4X4_UNORM + <stem>_anbc.astc / _mipN.astc),
--normal-map stores R,G as luminance + alpha (ANBC_TEXTURE_FLAG_NORMAL_MAP)
and scores those two channels, --format astc-float is HDR RGB from .hdr
(only .astc files: DDS has no HDR ASTC id). On an M5 with mips: bistro 537 textures
1.1 s total vs 101 s astcenc (89x; mip-0 PSNR 55.0 vs 60.9 dB, 96/324 within
3 dB -- the single-partition gap is wider than against Compressonator's BCn
since astcenc's search is far richer), 152 normal maps 0.42 s vs 205 s
(490x; 44.4 vs 48.1 dB on X,Y), 100 HDR images 0.14 s vs 15.7 s (111x; 44.1
vs 48.9 dB half-int); a 2048^2 albedo encodes in ~3 ms, a 1024x680 HDR in
~0.3 ms.
    c_api/build/anbc_compare data/bistro/Antenna_Metal_BaseColor.png --format astc --out /tmp
    c_api/build/anbc_compare data/normal/2299742237651021498.jpg --format astc --normal-map --out /tmp
    c_api/build/anbc_compare data/hdr/valid/0801.hdr --format astc-float --out /tmp
    c_api/build/anbc_compare data/bistro --format astc --out out/astc_bistro
    c_api/build/anbc_compare data/normal --format astc --normal-map --out out/astc_normal
    c_api/build/anbc_compare data/hdr/valid --format astc-float --out out/astc_hdr

Flags: --format bc7|bc6h|bc5|astc|astc-float (default bc7), --backend metal|vulkan (default metal on
       macOS, vulkan elsewhere), --xcheck (single image: both backends, per-mip PSNR + identical-block share),
       --normal-map (astc), --srgb (filter mips in linear light; LDR only), --no-mips, --refine-iters N,
       --cmp-quality Q (Compressonator quality, default 0.05), --astc-preset fast|medium|thorough, --models DIR,
       --threads N / --single-thread (Compressonator; default = all cores),
       --no-tensor-ops (BC7: scalar kernel only; otherwise both kernels are run
       and compared on M5-class GPUs).
In single-image mode each mip is also scored against a CPU box-filtered
reference and the tool exits non-zero if quality drops below a sanity floor.

Score / view the DDS outputs of a folder run against the originals (per-mip
PSNR, optional FLIP on mip 0, CSV; or a synced-zoom viewer for one texture;
the format is read from the DDS header, BC5 is scored on RG and viewed as a
normal map, BC6H is scored half-int / HDR-FLIP and viewed tone-mapped):
    python src/compare_dds.py --dds-folder out/bistro --original-folder data/bistro --flip --csv out/bistro/quality.csv
    python src/compare_dds.py --dds-folder out/bistro --original-folder data/bistro --image <stem> --mip 2
    python src/compare_dds.py --dds-folder out/normal --original-folder data/normal --flip
    python src/compare_dds.py --dds-folder out/hdr --original-folder data/hdr/valid --flip
    python src/compare_dds.py --dds-folder out/astc_bistro --original-folder data/bistro
    python src/compare_dds.py --dds-folder out/astc_normal --original-folder data/normal --normal-map
    python src/compare_dds.py --dds-folder out/astc_hdr --original-folder data/hdr/valid   (.astc chains via the astcenc CLI)
(pass --srgb here too if the DDS were generated with --srgb)

API: see c_api/include/anbc.h (anbcCreateDevice -> anbcLoadModel x2 (BC7 only)
-> anbcCreateTexture (RGBA8 or RGBA16F pixels) -> anbcCompress(format) -> anbcGetMip).
ASTC: ANBC_TEXTURE_FORMAT_ASTC_4x4_UNORM (RGBA8; + ANBC_TEXTURE_FLAG_NORMAL_MAP on
the texture for X,Y -> luminance + alpha, sample .ra) and
ANBC_TEXTURE_FORMAT_ASTC_4x4_FLOAT (HDR RGB, needs an HDR-capable ASTC decoder,
i.e. Apple GPUs from A13/M1). Neither takes a model.
Max texture size 4096^2 with mips (the single-dispatch mip generator's limit),
16384^2 without.
anbcGetDeviceInfo() reports the backend name and whether tensor ops are in use;
ANBC_COMPRESS_FLAG_NO_TENSOR_OPS forces the scalar kernel per call.
The GLSL ASTC tables are generated like the Metal ones:
    python src/astc_ise.py --emit-glsl > c_api/src/shaders/glsl/anbc_astc_tables.glsl
